# Design and Delivery Archive

The dated files in `specs/` and `plans/` record decisions and implementation
history. They are preserved so changes can be audited, but they are not current
product documentation and unchecked tasks are not a live backlog.

For current behavior, use these sources in order:

1. [`docs/FEATURE_STATUS.md`](../FEATURE_STATUS.md) for the implemented and
   absent capability inventory.
2. [`ARCHITECTURE.md`](../../ARCHITECTURE.md) for current package and authority
   boundaries.
3. [`docs/CLI.md`](../CLI.md) for the supported command surface.
4. Code and tests when a dated record conflicts with any current document.

Historical records may name removed native components, superseded provider
policies, earlier operating-mode revisions, or worktrees that no longer exist.
Those references describe their original milestone; they do not authorize
restoring obsolete architecture.
