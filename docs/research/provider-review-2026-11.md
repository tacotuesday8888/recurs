# Hosted provider review, November 2026

Reviewed November 18, 2026 against public vendor documentation and the
transports shipped in Recurs `0.1.0-alpha.11`. The review supports a new
window for nine hosted routes and two local runtimes, starting November 18,
2026 at 00:00 UTC and ending February 18, 2027 at 00:00 UTC (exclusive).
The original windows closed in October. The intervening dates stay expired.
Existing bindings can retain their policy revision only where the credential
destination, usage restrictions and accepted billing rules still match.
Account entitlement, access to particular models and live execution require
separate evidence. This review made no authenticated requests.

## Routes requiring changes or a narrower supported scope

Recurs' Chat Completions serializer reconstructs assistant history from text
and tool calls. Its Anthropic Messages serializer reconstructs text and
tool-use blocks. The following protocol findings concern the next request
after a tool result, which a successful model-list request cannot validate.
[Chat Completions serializer](../../packages/providers/src/local-openai-compatible.ts) ·
[Messages serializer](../../packages/providers/src/anthropic-messages.ts)

| Saved provider | Findings and action before activation |
| --- | --- |
| `deepseek-api` | The key, fixed OpenAI and Anthropic URLs, and metered API billing match. DeepSeek enables thinking by default. With tools, it requires the returned reasoning content on subsequent Chat Completions requests and documents a 400 when it is missing. Select the documented non-thinking mode on this route and verify the second tool round, or implement the required continuation. [Endpoints and pricing](https://api-docs.deepseek.com/quick_start/pricing/) · [Authenticated models](https://api-docs.deepseek.com/api/list-models/) · [Thinking and tool calling](https://api-docs.deepseek.com/guides/thinking_mode/) |
| `kimi-platform-api` | `api.moonshot.ai/v1` accepts bearer authentication for metered Kimi Platform API usage. The K3 series always enables Preserved Thinking. Its documented tool loop sends the complete assistant message back, including `reasoning_content`. Qualify a narrower compatible model or implement and test the required continuation before claiming support for K3 tool use. [Chat protocol](https://platform.kimi.ai/docs/api/chat) · [Platform pricing](https://platform.kimi.ai/docs/pricing/chat) |
| `minimax-api` | The standard key, `api.minimax.io/v1`, authenticated model listing and pay-as-you-go balance match. MiniMax's OpenAI guide requires complete assistant history during tool use. Plan keys consume included quota then eligible credits, and require distinct disclosure from standard API keys. The Anthropic base and model-list route match, but MiniMax specifies replaying the response's thinking, text and tool-use blocks for tool continuation. Retain the explicit credit acknowledgement, identify existing and new plans accurately, and qualify a complete tool round with the plan transport. [Plan transition](https://platform.minimax.io/docs/m-plan/token-plan-notice) · [Plan and credit billing](https://platform.minimax.io/docs/m-plan/faq) · [Messages API](https://platform.minimax.io/docs/api-reference/text-anthropic-api) · [Model listing](https://platform.minimax.io/docs/api-reference/models/anthropic/list-models) |

A subscriber can enable Extra Usage, which draws a purchased balance after quota. The old global, unrestricted subscription-only policy misses these conditions. Keep it closed until region, run context, client identity, paid fallback and tool continuation are handled. [Client rules](https://www.kimi.com/code/docs/en/kimi-code/community-guidelines.html) · [Regions and protocol](https://www.kimi.com/code/docs/en/kimi-code/models.html) · [Membership and Extra Usage](https://www.kimi.com/code/docs/en/kimi-code/membership.html) |

Clients should identify themselves and provide a stable conversation identifier. The subscription can use the Console balance beyond quota when Extra Usage is on, including by default for Go Teams. Update the integration and verify session handling. Permit a strict subscription-only selection only when that billing boundary can be enforced. [Go clients, quotas, billing and endpoints](https://opencode.ai/docs/console/go/) |

Require an enforceable credits-only route, or express the user's upstream billing sources and obtain acknowledgement before enabling the route. [Authentication](https://openrouter.ai/docs/api_reference/authentication) · [Credits](https://openrouter.ai/docs/faq) · [BYOK order and fallback](https://openrouter.ai/docs/guides/overview/auth/byok) |

Configured personal or organization upstream keys can be used automatically, with direct provider billing. Reconcile the credential destination and billing consent before renewal. [Product example](https://kilo.ai/gateway) · [Gateway integration](https://kilo.ai/docs/gateway) · [Authentication and upstream keys](https://kilo.ai/docs/gateway/authentication) · [Billing](https://kilo.ai/docs/gateway/usage-and-billing) |
