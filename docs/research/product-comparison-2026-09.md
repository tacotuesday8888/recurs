# Product comparison: TypeScript coding CLIs — September 9, 2026

## Scope and evidence

This is a source-and-documentation comparison for Recurs product polish. No peer was installed, authenticated, or run live for this review, and no speed, model-quality, safety superiority, or market-share ranking is claimed. Public GitHub metadata, pinned source files/tests, official documentation, and npm registry package metadata were read on September 9, 2026. Source tests were inspected, not executed.

Recurs baseline: `0.1.0-alpha.10`, checkout `a968cd3f0e31b3dc87f66b192ab8cc048e264b38`, before this phase's implementation. References to gaps describe that baseline. Its [CLI](../CLI.md), [feature inventory](../FEATURE_STATUS.md), and [release evidence](../RELEASE_READINESS.md) already establish a working installed product with durable execution identity, bounded delegation, independent review/repair, and explicit apply. The next work should improve everyday control and presentation without replacing that engine.

Antigravity is excluded as a primary peer, as requested. Gemini CLI is only an ancestry/source reference here; it is not included as a current individual-user product recommendation. Qwen's independent development is evaluated on its own current source.

## Three practical priorities

1. **Make appearance a real user setting.** Add semantic palettes for system, dark, light, and a small number of named themes; a searchable picker previews immediately, Enter saves, Escape restores the prior theme. Apply one palette to conversation, tool output, approvals, onboarding, model picker, tree, and inspector. Keep terminal-default foreground/background and no-color paths. Recurs currently hard-codes cyan, ANSI/256-color layer colors, and dim styling in `terminal-style.ts`, with separate Markdown/editor styling in `terminal-ui.ts`; switching only the header would leave a fragmented result.
2. **Show and edit the effective model route where the task is being configured.** Display parent model/effort and each specialist's actual inheritance or override with a reason. Let users select a saved eligible connection from a picker, rather than copying an opaque connection ID. Recurs already has validated routing and fresh-session switching; the missing part is discoverability and a unified preview. Preserve immutable past execution pins and clearly state when a change affects a fresh session or future child work.
3. **Make setup easy to correct and child work easy to inspect.** Keep Start coding as the short path. Give optional team setup a visible step/back path, saved draft, and final effective configuration review. Give execution inspection a parent breadcrumb and previous/next sibling actions without losing selection/scroll. These are adjacent UI improvements, not a request to introduce a daemon, autonomous organization changes, or unlimited child steering.

These are judgments from the evidence below, not benchmark conclusions. Root owns theme/UI decisions, the onboarding workstream owns setup navigation, and the hierarchy workstream owns execution behavior; coordinate shared controls before implementation.

## Concrete patterns and decisions

### Themes: preview is a transaction, not just colored text

OpenCode's theme dialog saves the initial selection, previews on movement/filter, and restores it on cleanup unless selection was confirmed. Pi separates preview, select, and cancel callbacks and marks the active theme. Cline clears preview on dialog cleanup and derives a visible row window from terminal height; its themes have swatches and current-selection labels. These are three useful implementations of the same user contract, across two renderers. [OpenCode picker](https://github.com/anomalyco/opencode/blob/830d5eb5354874105cc31599635a80c1662609e8/packages/tui/src/component/dialog-theme-list.tsx) · [Pi picker](https://github.com/earendil-works/pi/blob/acaa253cc8e3f159e6100b6f3874861b1f0bfc99/packages/coding-agent/src/modes/interactive/components/theme-selector.ts) · [Cline picker](https://github.com/cline/cline/blob/2dd8f11ada77947b3a8fb04303ca05b4527f391b/apps/cli/src/tui/components/dialogs/theme-picker.tsx)

OpenCode documents system colors and terminal-default foreground/background alongside named palettes; adopting that escape hatch is more useful than shipping dozens of presets. Cline tests readable selection foreground/background pairs and complete semantic color coverage. Qwen tests light/dark detection plus parity between its two terminal implementations. **Adopt semantic color tokens and transactional preview; retain pi-tui until a measured renderer limitation justifies replacement.** [OpenCode theme guide](https://opencode.ai/docs/themes/) · [Cline palette tests](https://github.com/cline/cline/blob/2dd8f11ada77947b3a8fb04303ca05b4527f391b/apps/cli/src/tui/themes.test.ts) · [Qwen detection tests](https://github.com/QwenLM/qwen-code/blob/0805135800796cf3bd59c2491e6212476267c7bd/packages/cli/src/ui/opentui/theme-auto.test.ts)

Acceptance: preview then Escape leaves stored preference and draft unchanged; Enter persists across restart; all surfaces repaint; the highlighted row remains visible in a short window; unknown theme IDs fall back visibly; light, dark, terminal-default, and `NO_COLOR` render readable selection/status text. If custom JSON palettes are introduced, reject cycles/unknown semantic references and test precedence. OpenCode's tests cover circular color references and directory ordering. [OpenCode theme tests](https://github.com/anomalyco/opencode/blob/830d5eb5354874105cc31599635a80c1662609e8/packages/tui/test/theme.test.ts)

### Model routing: separate intent, effective route, and historical execution

OpenCode's per-agent model falls back to the invoking parent's model for subagents. Kilo documents distinct main, small, and subagent slots and per-agent defaults; some small-model fallback can route to its gateway, so a private/local selection needs an explicit effective-route display. Qwen supports `inherit`, a configured `fast` route, explicit provider/model, and user-defined grades constrained by allowed grades. These are understandable abstractions, but none should override Recurs's billing eligibility or authority checks. [OpenCode agents](https://opencode.ai/docs/agents/) · [Kilo model routing](https://kilo.ai/docs/code-with-ai/agents/model-selection) · [Qwen subagent selectors](https://qwenlm.github.io/qwen-code-docs/en/users/features/sub-agents/)

Pi exposes a model picker, explicit startup-default action, and a scoped model cycle. That separates temporary selection from saved preference. In Recurs, `/model` already lists saved connections, including billing/effort, and creates a fresh pinned session after confirmation; `guided-onboarding.ts` already filters specialist routes against operating-mode eligibility. **Retain those guarantees; adopt a picker and a compact effective-route summary.** Do not claim that model switching is wholly absent. [Pi controls](https://github.com/earendil-works/pi/blob/acaa253cc8e3f159e6100b6f3874861b1f0bfc99/packages/coding-agent/README.md) · [Recurs model command](../../packages/cli/src/commands/model.ts) · [Recurs onboarding](../../packages/cli/src/guided-onboarding.ts)

Acceptance: one eligible provider gives a sensible inherited default; unavailable and policy-ineligible routes explain why; changing a saved default does not rewrite a completed execution; active work cannot silently switch billing/model; reviewer authority remains read-only even when its model changes. Do not adopt an “auto cheapest/best” route until actual evidence and user policy support it.

### Child navigation: promote real relationships, not configured personas

OpenCode's child footer derives siblings from exact `parentID`, orders by creation time, shows position within siblings, and exposes parent/previous/next navigation. Pi's *example extension* offers collapsed live summaries and expanded per-task output/usage; it is not equivalent to built-in durable company orchestration. Its example propagates Ctrl+C to child processes and supports bounded parallel/chained work. **Adopt navigation and compact summary patterns; retain Recurs's exact execution IDs, ownership checks, durable transcripts, and explicit reviewed apply.** [OpenCode child footer](https://github.com/anomalyco/opencode/blob/830d5eb5354874105cc31599635a80c1662609e8/packages/tui/src/routes/session/subagent-footer.tsx) · [Pi extension example](https://github.com/earendil-works/pi/blob/acaa253cc8e3f159e6100b6f3874861b1f0bfc99/packages/coding-agent/examples/extensions/subagent/README.md)

Recurs already separates a configured team tree from real executions and cancels an owned execution plus descendants. Its inspector returns to the execution list; adding sibling/parent shortcuts can reduce repeated navigation without introducing an editable child composer. Route labels should distinguish “configured but inactive” from an actual launched model. The current tree counts and inspector sources provide the baseline, not a mockup. [Recurs tree](../../packages/cli/src/terminal-agent-tree.ts) · [Recurs inspector](../../packages/cli/src/terminal-execution-inspector.ts)

Do not copy permission semantics without review. OpenCode explicitly separates parent *session* deny rules from parent *agent* restrictions. Continue's sampled subagent executor temporarily sets a shared permission service to allow every tool; that is incompatible with Recurs parent ceilings. Pi explicitly has no built-in process/filesystem/network permission system. Roo's historical CLI defaults to auto-approval and timed follow-up selection. These are concrete reasons to reuse presentation ideas while retaining Recurs's authority model. [OpenCode permission derivation](https://github.com/anomalyco/opencode/blob/830d5eb5354874105cc31599635a80c1662609e8/packages/opencode/src/agent/subagent-permissions.ts) · [Continue executor](https://github.com/continuedev/continue/blob/5522c6f44ca0ac3528b37244818fbfa39b5af470/extensions/cli/src/subagent/executor.ts) · [Pi boundary](https://github.com/earendil-works/pi/blob/acaa253cc8e3f159e6100b6f3874861b1f0bfc99/README.md) · [Roo defaults](https://github.com/RooCodeInc/Roo-Code/blob/b867ec9145750d0ae1ff7f02d35406e9bf2a0b16/apps/cli/README.md)

### Onboarding: make the short path obvious and the long path reversible

Cline documents explicit authentication before OAuth use and a fast failure in non-interactive sessions without saved credentials. Continue separates direct prompt/headless invocation from session listing. Roo's shim-based CLI is evidence that a terminal entrypoint can reuse an existing engine, but its archived status and permissive defaults make it unsuitable as a current product baseline. **Retain Recurs's runtime separation and explicit login; improve setup ergonomics rather than adding another runtime.** [Cline auth and entrypoints](https://github.com/cline/cline/blob/2dd8f11ada77947b3a8fb04303ca05b4527f391b/apps/cli/README.md) · [Continue entrypoints](https://github.com/continuedev/continue/blob/5522c6f44ca0ac3528b37244818fbfa39b5af470/extensions/cli/README.md)

Recurs's alpha.10 installed tests already prove Start coding and Quick/Guided/Deep proposal save/reopen/approve. That is a foundation, not a reason to retain every wizard step. The baseline setup UI advertises Escape as cancel; it has no uniform previous-step action. Its choices span model, authority, operating mode, topology, routes, design depth, company structure, and project context. A compact final summary should answer: which model, which permissions, how much parallel work, what each specialist inherits, and what starts now. Keep detailed company formation optional and avoid presenting billing-policy identifiers as the user's primary choice labels.

Acceptance: return to the prior step without losing a typed answer; resume a saved proposal without another model request; cancellation starts no coding task; a single-model setup needs no specialist route ceremony; changing a configuration preference clearly distinguishes saved future defaults from the current session. Preserve the existing source and installed regressions for the saved-proposal bug.

## Suggested sequence and exclusions

Start with shared semantic palettes and accessible picker behavior, then connect the same picker/summary components to model and setup surfaces. Add parent/sibling inspector navigation after confirming exact hierarchy behavior. Verify with the installed artifact at ordinary and small terminal sizes, light/dark/no-color, interrupted setup, and a persisted multi-execution fixture. The acceptance targets are fewer confusing decisions and reliable control, not a claim of superior model intelligence.

Do not expand this polish pass into arbitrary executable plugins, a background daemon, cloud sessions, automatic paid model routing, or new credential formats. OpenTUI appears in several peers, but that alone does not justify rewriting Recurs's working TypeScript/pi-tui presentation. Continue and Roo remain valuable source references with explicit maintenance caveats. Qwen's promotional benchmark/feature-parity claims were not adopted as independent evidence.
